# Changelog

All notable changes to OpenCode Playbook are recorded here. Dates are absolute.

## Unreleased

No implementation is claimed beyond the planning checkpoint below.

## 0.0.1 — 2026-09-17

### Added

- Validated corrective design for a faithful 49-rule OpenCode-native playbook.
- Executable TDD release plan covering rule parity, sixteen skills, safe
  transactions, runtime verification, public documentation, visual quality,
  GitHub publication, security settings, Pages, and the 0.1.0 release.
- ADR 0002 selecting native progressive disclosure and superseding the
  prototype rule-delivery architecture.
- Canonical plan and documentation indexes distinguishing current artifacts
  from historical 2026-09-16 input.
- Truthful planning-stage `.env.example`, backlog, contributor, security, and
  current handoff records, plus a byte-preserved dated prototype handoff.
- Reproducible source evidence pinning Claude Code Playbook commit
  `5db68e347a65e511cc378b0598a6aac6655845bd` at version `0.1.12` and Codex
  Playbook commit `b79080ad6f3f9605b60d4722265a5d271ea2e540` at version `0.1.3`, consumed
  only through verified pinned `git show` and `git ls-tree` object reads.
- Executable planning verification with explicit working-tree and committed
  inventories, including untracked-file, link, handoff, source-pin, and diff
  checks.

### Changed

- Replaced the planned 42-rule monolith and three-skill product with a lean
  authority router and sixteen native skills preserving all 49 canonical rules.
- Restricted the planned 0.1.0 support claim to stable OpenCode 1.18.31 and
  explicitly marked OpenCode v2 untested and unsupported.
- Expanded the planned installer and restore contract with exact format-2
  schemas, XDG-aware roots, concurrency control, strict symlink refusal,
  signal-safe rollback, isolated runtime proof, and verified publication.
- Moved public repository creation to the reviewed 0.0.1 planning checkpoint
  and required every later candidate to pass specification and quality review
  before its immutable checkpoint tag and immediate branch/tag push.
- Required exact-tip review of each complete candidate, including review
  records, current status, version, backlog, and handoff, before tagging.
- Replaced mutable status predictions with durable discovery gates; specified
  physical root identity, isolated environment-only runtime credentials, a
  tested POSIX skill parser, bounded publication polling, exact PR integrity,
  full-tree dependency inspection, and explicit staging allowlists.
